Adaptive null-move with zugzwang guard (RESEARCH.md Code Examples §"Adaptive Null-Move", replaces V7 search.cpp:229-258):
  - Gate: UseNullMove && do_null && !in_check && !zugzwang_risk && depth >= 3 && static_eval >= beta
  - zugzwang_risk = (board.non_pawn_material(board.side_to_move) == 0)
  - R = 3 + depth/4 + std::min((static_eval - beta) / 200, 3)
  - If null_score >= beta and depth >= 12: verification re-search at same R; only return beta if verification confirms
  - If null_score >= beta and depth < 12: return beta directly
  - Use triangular PV (no allocations) — Plan 03-01 has already made this available via info.search_stack

Two-level LMR re-search (RESEARCH.md Pitfall 3, canonical Stockfish/Ethereal/Berserk form, replaces V7 search.cpp:324-332):
  // Step 1 — reduced zero-window:
  score = -alpha_beta(board, depth - 1 - R, -alpha - 1, -alpha, ...);
  if (score > alpha && R > 0) {
      // Step 2 — zero-window re-search at FULL depth:
      score = -alpha_beta(board, depth - 1, -alpha - 1, -alpha, ...);
  }
  if (score > alpha && score < beta) {
      // Step 3 — full-window re-search at FULL depth (PV):
      score = -alpha_beta(board, depth - 1, -beta, -alpha, ...);
  }
  Context adjustments to R (RESEARCH.md D2 §3.2): subtract 1 on PV nodes; add 1 on cut nodes; subtract 1 if improving; force R=0 if in_check. Existing LMR_TABLE at search.cpp:32-43 stays — only the reduction-context delta and the re-search ladder change.

RFP (Reverse Futility Pruning) — gated by UseRFP, fires near root before move generation:
  if (depth <= 8 && !in_check && !is_pv && static_eval - rfp_margin(depth) >= beta) return static_eval;
  rfp_margin(depth) ≈ 100 * depth (tunable; cite RESEARCH.md D2 §3.3 in comment)

Futility pruning — gated by UseFutility, in move loop at frontier nodes:
  if (depth <= 3 && !in_check && !is_pv && !gives_check(m) && !is_capture(m)
      && static_eval + futility_margin(depth) < alpha) continue;
  futility_margin(depth) ≈ 200 * depth

LMP (Late Move Pruning) — gated by UseLMP, in move loop after move ordering:
  if (depth <= 8 && !in_check && !is_pv && move_count >= lmp_threshold(depth)
      && !is_capture(m) && !gives_check(m)) break;  // (or continue depending on local convention)
  lmp_threshold(depth) ≈ 4 + depth * depth (canonical table)
