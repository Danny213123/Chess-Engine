## Plan 03-05 Task 3 — TSan 16-thread × 60-second stress gate (PAR-03 / D-08)

**Status:** DEFERRED on the Windows dev host.
**Blocking:** Plan 03-06 ship-SPRT (`bash scripts/tt_tsan_stress.sh` re-runs as part of the final acceptance gate).

### Why this is deferred

ThreadSanitizer (`-fsanitize=thread`) is unavailable on MSVC — the only
C++ toolchain we have configured on the Windows dev host. Per PATTERNS.md
Shared Pattern 5 (build-host-only deferred gates) and the precedent set by
Phase 1's `.continue-here.md`, runtime gates that require Linux/macOS/WSL
ship as plumbing on the dev host and run on a build host downstream.

Plan 03-05 Tasks 1 (lockless Hyatt-Mann XOR TT — commit `d4f1217`) and 2
(TSan stress harness sources + CMake target + shell wrapper — commit
`c1843f6`) ARE complete on the dev host. Task 3 is purely the runtime
verification — the source/script/CMake plumbing is in place.

### Reproduction

On a build host with `clang++` (preferred) or `g++`:

```bash
# From repo root:
git pull origin main
bash scripts/tt_tsan_stress.sh
```

Override the compiler if needed:

```bash
TSAN_CXX=g++ bash scripts/tt_tsan_stress.sh
```

Wall-clock: ~75 seconds (≈10s CMake configure + build, 60s harness run, ~5s
worker join).

### Pass criterion

Script exits 0 and prints:

```
PASS: TSan clean over 16 threads x 60s
```

### Fail behavior

Script exits 1, dumps the captured TSan log to stderr, and prints:

```
FAIL: TSan reported races
```

If the script fails, the most likely culprits (per RESEARCH.md Pitfall 1):

1. Probe loading `data` BEFORE `xkey` (must be xkey-then-data — implementation
   in `src/chess_engine/engine/v7/src/tt.cpp` does the right order, but
   verify if a future edit reorders).
2. Store writing `xkey` BEFORE `data` (must be data-then-xkey — same).
3. Any non-`memory_order_relaxed` atomic ordering accidentally introduced
   (TSan may flag suspicious release/acquire patterns).

Do **NOT** proceed to Plan 03-06 ship-SPRT until TSan exits clean.

### Optional confirmation passes

D-08 wording is "any race detection = fail". Two or three additional runs
reduce false negatives on machines with low core count (where some
interleavings are rarer). Record host platform, compiler version, and run
timestamp in the commit message:

```bash
git commit --allow-empty -m "phase(03-05): TSan 16t x 60s clean — <platform> <compiler> <date>"
```
