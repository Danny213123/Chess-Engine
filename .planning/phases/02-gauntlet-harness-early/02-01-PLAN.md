<objective>
Close the V7 UCI gap (#2 + #3 from project_v6_v7_uci_gaps.md) so v7_uci can be driven correctly by fastchess in Phase 2's gauntlet.

Purpose: fastchess sends `setoption name Hash value 64` and `go wtime 10000 btime 10000 winc 100 binc 100` on every match. v7_uci currently silently drops the former (lines 207-210) and ignores the latter in `go` (line 184 comment) — every move would run at the hardcoded 5000 ms `DEFAULT_GO_TIME_MS` regardless of the gauntlet's TC. Without this fix the V7-vs-V6 gauntlet would be physically running but measuring nothing the user thinks it is measuring.

Output: extended `v7_uci` UCI loop + subprocess unit tests proving the new branches behave correctly without regressing Phase 1 `depth` / `movetime` handling.
</objective>
