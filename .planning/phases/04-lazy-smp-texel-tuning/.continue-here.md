**Status:** DEFERRED on the Windows dev host.
**Blocking:** Plan 04-02 PAR-09 gauntlet (must confirm Lazy SMP actually scales before

### Why this is deferred

The PAR-07 NPS-scaling sentinel requires:
1. A compiled `v7_engine.pyd` native module (needs CMake + C++17 toolchain).
2. A quiet single-CPU host where background load doesn't skew the 4t/1t ratio

load is variable). Per PATTERNS.md Shared Pattern 5 and the Phase 1/3 precedent,
runtime benchmark gates ship as plumbing on the dev host and run on the build host.

implementation — commit `e06865e`) ARE complete on the dev host.

### Pass criterion

Test exits 0 and prints output containing:


where `ratio >= 3.0`. The exact measured values should be recorded in the Result

### Fail behavior

Test fails with:


`m.def("search")` has `py::call_guard<py::gil_scoped_release>()`. Also check that
helper threads do not touch Python objects (thread_pool.cpp touches no py:: APIs).

Do NOT proceed to Plan 04-02 PAR-09 gauntlet until this test passes.

## Plan 04-02 — PAR-09 self-play 4t-vs-1t SPRT gauntlet (PAR-09)

**Status:** DEFERRED on the Windows dev host.
**Blocking:** Plan 04-03 (Texel pipeline). PAR-09 must PASS before Texel work
begins so any Elo delta in Success Criterion #6 (tuned vs untuned V7) attributes
cleanly to the tune rather than to an unmeasured SMP regression.

### Why this is deferred

The PAR-09 gauntlet requires:
1. A compiled `v7_uci` binary (needs CMake + C++17 toolchain — absent on
   the Windows dev host; MSVC unavailable).
2. A working fastchess install (provisioned via `tools/fetch_fastchess.py`
   on the build host).
3. ≥500 games of pentanomial SPRT at TC=10+0.1 → ~3-4 hours of wall-clock
   on a quiet machine (1000 games at the D-10 safety floor).
4. A quiet single-CPU host so the 4t side isn't starved by background load
   (would inflate variance and produce a spurious H0 / inconclusive verdict).

Per PATTERNS.md Shared Pattern 5 and the Phase 1/3 precedent, build-host
gauntlet gates ship as plumbing on the dev host and run on the build host.

Plan 04-02 Tasks 1 (per-side options + narrow D-09 lift — commit `e5f24b1`)
and 2 (this recipe — commit follows) ARE complete on the dev host. The dry-run
preview path (`--dry-run`) lets a developer verify the constructed fastchess
argv before kicking off the multi-hour run.

### Reproduction

On a build host with CMake + C++17 toolchain + `uv` + a built `v7_uci`:

```bash
# From repo root:
git pull origin main
# Ensure v7_uci is built (PAR-07 + PAR-08 should already be green here):
python3 -m uv run --group dev python -c "from chess_engine.engine.v7 import chess_algorithm as v7; v7.ensure_available(auto_build=True)"
# Ensure fastchess is provisioned (vendored or fetched):
python3 -m uv run --group dev python -m tools.fetch_fastchess

# Sanity-check the constructed command via --dry-run first:
python3 -m uv run --group dev python -m tools.gauntlet run \
  --binary-a src/chess_engine/engine/v7/build/v7_uci \
  --binary-b src/chess_engine/engine/v7/build/v7_uci \
  --engine-a-options "Threads=4;Hash=64" \
  --engine-b-options "Threads=1;Hash=64" \
  --tc 10+0.1 \
  --concurrency 1 \
  --book tools/books/8moves_v3.pgn \
  --games 1000 \
  --sprt-elo0 0 --sprt-elo1 10 --sprt-alpha 0.05 --sprt-beta 0.05 \
  --pentanomial \
  --output-dir .planning/gauntlets/phase4-par09 \
  --dry-run

# Then run the gauntlet for real (drop --dry-run). NOTE: Plan 04-02

  --binary-a src/chess_engine/engine/v7/build/v7_uci \
  --binary-b src/chess_engine/engine/v7/build/v7_uci \
```

After the run completes, commit `.planning/gauntlets/phase4-par09/summary.json`
and `.planning/gauntlets/phase4-par09/games.pgn` to git as the audit trail
(per D-13 pattern).

### Pass criterion

The SPRT contract is the formal gate:

- **SPRT verdict: H1 accepted** (LLR crossed the upper bound at `elo1=10`)
- **Lower-bound Elo >= 0** (point estimate's 95% CI lower bound — 4t is
  strictly not worse than 1t)
- **Time-forfeit count == 0** (any forfeit triggers manual investigation per
  GAUNT-07 / WARNING-3)

The CONTEXT D-10 / ROADMAP SC#3 **>=40 Elo target** is the point-estimate
goal documented for the human reviewer — the SPRT bound is the binary
pass/fail gate. A run that achieves `H1 accepted` with point estimate
30-40 Elo still PASSES PAR-09 (the SPRT contract was met), but the human
reviewer should note it as a soft signal that the SMP scaling is at the
floor of what Berserk/Ethereal precedent predicts.

### Fail behavior

If `SPRT verdict: H0 accepted` OR lower-bound Elo < 0:

**Bisection protocol (Pitfall 5 — narrow the failure surface before re-opening
Plan 04-01):**

1. Re-run with `Threads=2;Hash=64` vs `Threads=1;Hash=64` (same other params,
   same games count). This isolates the 2t-vs-1t base case.
2. **If 2t-vs-1t also FAILS** (verdict H0 or lower-bound < 0): suspect Pitfall 1
   (shared mutable per-thread state — Worker tables aliased via reference rather
   than value-copied). Re-open Plan 04-01 Task 2 (c) — verify the Worker struct's
   `history`, `counter_moves`, `continuation_history`, `capture_history` fields
   are zero-initialized arrays inside Worker, NOT references to Engine members.
   Plan 04-02 is REJECTED until 04-01 ships a fix.
3. **If 2t-vs-1t PASSES but 4t-vs-1t fails**: suspect TT contention (Plan 04-01
   PATTERNS open question). Revisit Phase 3 D-07 TT sizing — the Hyatt-Mann
   XOR-lockless TT may need a larger replacement window when 4 threads contend
   on the same buckets. Re-run with `Hash=256` (per side) as the first diagnostic
   step before treating it as a structural defect.

Both bisection runs land in `.planning/gauntlets/phase4-par09-bisect/`
(separate output dirs so the original PAR-09 evidence is preserved).
